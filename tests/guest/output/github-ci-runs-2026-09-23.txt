The workflow is .github/workflows/build-apk.yml; it calls tools/build_launcher_apk.sh unchanged, on
windows-latest, with the SDK components the local build uses pinned to the same versions.

                                It would NOT install over the local build:

Run 35893873011  failure        "Build guest images": exit 74, output stopping mid-probe, no message.
                                NOT ROOT-CAUSED. Two hypotheses were tested locally and BOTH are wrong:
                                (a) the `file -b` in the summary line -- a failing file(1) does not abort
                                    that echo (measured: exit 0, prints "no file(1)");
                                (b) the echo line generally -- same measurement.
                                The assignment form `sz="$(tool | awk)"` DOES abort under `set -euo pipefail`
                                (measured, status 127), so the death was in a probe's tool invocation --
                                but the status was 74 (EX_IOERR literally), which no local reproduction
                                produced. What is in place now is instrumentation, not a fix: both guest
                                scripts carry `set -E` + an ERR trap that names file, line and command.
