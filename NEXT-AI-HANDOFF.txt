1c. 2026-10-24 (later) — C46 FIXED: Java thread APIs were given guest tids
-----------------------------------------------------------------------
- **Root cause:** `UnityPlayer.nativeRender` calls `android.os.Process.setThreadPriority(<tid>)` with a
  **guest** tid (Unity got it from `gettid()`). ART resolves *host* tids, so every call threw
  `IllegalArgumentException: Given thread N does not exist` (135 in the first second on TT2). The pending
  exception left nativeRender half-run and the engine's main thread parked in an il2cpp condvar that
  nothing could wake — the "shared Unity startup convvar" C46.
- **Fix:** guest threads carry their bound host's Linux tid (`GuestThread::host_tid`, set in
  `BindCurrentHostThread`); `GuestProcess::HostTidOf()` maps guest -> host; `ForwardingJni` resolves
  `Process.setThreadPriority`'s two overloads once and rewrites the tid argument (unknown ids pass through
  untouched). Resolver installed once in `BootBridge`.
- **Verified on the tablet (each repack carries the engine):** TT2 consent screen works, city intro runs at
  ~53 M guest instr/s; CD2 reaches its main menu + "Welcome Back / enter your name"; ABE renders its title
  and data-consent dialog; Rolling Sky no longer stalls but now exits on an unrelated provider-permission
  crash (C47).
- **Watch out:** ABE did not accept injected taps on its consent dialog (C48); verify with a second run
  before diagnosing. Rolling Sky's `.rb` copy calls the original install's non-exported
  `IpcProvider` (C47).
- Engine gate re-run after the change: see `build/gate-*.log` / `/tmp/engine-tests2.log` in-session;
  all suites 0 failures.


1b. 2026-10-24 — C46 is not a deadlock; the stall meter was lying
-----------------------------------------------------------------
- **The "no guest instruction retired in 10 s" stall was a false positive.** Unity's render loop calls
  JNI/GL thunks every few thousand instructions, so it never retires a whole 200k-instruction slice and
  `slices()` alone read zero for ten minutes while the guest was swapping 35 frames/s. Fixed:
  `AbiContext::host_activity()` (syscalls + host-slot dispatches); the profiler prints
  `alive: ... sub-slice stints, not a stall` while that moves. The `stall:` report now means quiescence.
- **TT2's live wall is il2cpp-side, not the libunity condvar previously named.** Clone 4245
  `UnityMain` waits at futex `0xff2f52c0` (word 0x4) that is never woken; its stack is
  `libil2cpp+0x35e830 <- libc+0x81927 (pthread_cond_wait) <- +0x46d17c <- +0x470840 <- +0x46d17c <-
  +0x46d208` (a poll loop over a byte flag). The guest keeps drawing (`glDrawElements` ~160/s, textures
  bound, ~35 swaps/s, SurfaceFlinger timestamps present) but the screen is black and the game logic
  never advances past `cached new terms`.
- **Java side is healthy.** `UnityChoreographer` (a Java thread, adopted as guest 4277) is inside
  `Choreographer.doFrame -> $Proxy11.doFrame -> bitter.jnibridge.JNIBridge.invoke`; the pump calls
  `longValue()`/`postFrameCallback` ~30/s; Java `UnityMain` is inside `UnityPlayer.nativeRender`.
- **Thread creation ends after the first 4 s** (31 clones, all from 4244 `UnityMain`; per-clone trace).
- **Found:** `Process.setThreadPriority(<guest tid>)` throws `Given thread 4246 does not exist` from
  `nativeRender` (135 times at startup). Java thread APIs resolve host tids; ours are synthetic. Fix =
  translate guest tid -> bound host tid for those calls in the forwarding bridge.
- **New diagnostics in the debuggable launcher build:** per-clone trace, `jni_pending` counter, JNI
  call trace (first stall, 300 lines), `ArtJava::DumpThreads()` Java thread dump (second stall — `kill
  -3` does nothing for a non-debuggable app), EGL/GL counters per stall window, wait-object memory
  window in `StallReport`, stacks for parked clones, futex wake stats.
- **Next:** (1) symbolise the il2cpp wait via Il2Cpp code registration + the APK's
  `assets/bin/Data/Managed/Metadata/global-metadata.dat`; (2) guest→host tid translation for
  `android.os.Process.setThreadPriority`; (3) sample the guest's own framebuffer to tell "black loading
  screen" from "empty scene".

1a. 2026-10-21 — the tgkill decode and four more engine gaps (C40–C45)
-----------------------------------------------------------------------
- **`tgkill(tgid, tid, sig)` was decoded as `tkill(tid, sig)`** in core/syscall/monitor.cpp. The
  target tid landed in the signal field, so `tgkill(4242, 4246, 30)` became `tgkill(4242, 4242, 4246)`

  Fixed + new monitor lane (233 checks). **TT2 now boots to its title, CD2 to its GDPR dialog.**
- **C41 was `glTexImage3DOES`.** Unity stores the result of `eglGetProcAddress("glTexImage3DOES")` and

  added + device lane. **CD2 → GDPR/loading, ABE → publisher splash, Rolling Sky → publisher splash.**
- **C43: synchronous SIGSEGV delivery.** A guest data/fetch fault now becomes a SIGSEGV frame
  (si_code/si_addr/fault_address) and resumes at the guest handler when one is installed; SIG_DFL, a
  blocked signal, a fault inside the handler, or a full delivery stack stays fatal. **Cars 3's Mono JIT
  null is now a handled NullReferenceException** instead of killing the process. 692 thread checks.
- **C44: VADDHN family + Tier I VectorLogicalShiftRight/VectorNarrow.** Dynarmic's A32 decoder had
  VADDHN/VRADDHN/VSUBHN/VRSUBHN commented out; libunity's `vaddhn.i16` stopped Cars 3 as

1n. 2026-10-26 (iOS S1g) — the window was never reserved: MAP_FAILED is not nullptr
---------------------------------------------------------------------------

1t. 2026-10-26 (iOS S1m) — KitKat's null app: the game library's JNI_OnLoad never ran
---------------------------------------------------------------------------
- The black screen was not a GL problem. `dlxSurfaceChanged` (libdlgl.so, 0x37410) only *reads*
  `DLApp::_currentInstance`; the writer is `libandroidkitkat.so`'s JNI_OnLoad (0x2b574): it `new`s a

  main app" line (tag tApp) in the log was the tell.

  assets/rb32/libdlgl.so) it boots libdlgl first, then every bundled library whose DT_NEEDED reaches one
  already in the order. Both hosts call it — the Android runtime (`rb_runtime_boot`) and the iOS session.
  The iOS session now picks the DLGL profile from the APK's contents, not the library's name.
- `android_base` gained Throwable/Exception/Error/NoClassDefFoundError and the common throwables, so a
  guest's FindClass("java/lang/Error") on an error path no longer turns into a second pending throw.

1y. 2026-10-28 (iOS S1r) — the ARM fault is the Tier I IR pool, bounded in build 8
---------------------------------------------------------------------------
- Source-level confirmation: `PrependNewInst +44` is the return from `Pool::Alloc`. Every `IR::Block`
  eagerly allocates 104 × 4096 = 416 KiB; the old 8192-block Tier I cache could reserve ~3.2 GiB.
  `Pool::AllocateNewSlab` never checks malloc, so a failed allocation makes the next placement-new write
  through null. Android Tier J releases each IR block and bounds its code cache to 64 MiB.
- Build 8 caps `InterpExecutor::kBlockCacheLimit` at 128 (~54 MiB worst case). This is the first-frame
  fix candidate; a later Dynarmic patch can reduce the 4096 initial slab and restore a larger cache.
- Build-8 CI `41171450697` green; IPA 2,056,945 bytes, commit `3a5a30b`, SHA-256
  `8a5e1b51…4208`. The translation-site diagnostics from build 7 remain in the crash line.
