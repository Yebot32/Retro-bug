4. Tooling notes and gotchas
----------------------------
- Build the launcher WITHOUT the bulk clean (both build scripts trip the session's safe-delete
  guard). Same trick for each:
      sed 's|^rm -rf "\$OUT"$|mkdir -p "$OUT"|' tools/build_launcher_apk.sh > build/build_launcher_noclean.sh
      sed 's|^rm -rf "\$OUT"; mkdir -p|mkdir -p|' tools/run_java_tests.sh > build/run_java_noclean.sh
  ROOT resolves correctly because the copies sit one level down. Delete them afterwards.
- Version: versionCode = `git rev-list --count HEAD`, versionName = `0.1.<count>`;
  RB_VERSION_CODE / RB_VERSION_NAME override. So committing changes the next build's version:
  the code at eb56d3b+2 uncommitted built as 0.1.238, and the same code committed is 0.1.240.
- **Under a DSH file sandbox, msys `bash` and `ninja` cannot create their signal pipes** ("fatal
  error - couldn't create signal pipe, Win32 error 5"), so every `.sh` build script dies before
  doing anything and `ninja` hangs with no child compiler. Two ways through: run the build with
  the sandbox widened, or drive the already-configured tree directly with the SDK's own ninja as
  a native exe — `"$LOCALAPPDATA\Android\Sdk\cmake\3.31.6\bin\ninja.exe" -C build/launcher-arm64`
  (that compiles and links the engine fine; only the APK packaging step needs the script).
- The engine is baked into every CONVERTED game's APK, so an engine fix needs the game re-repacked
  before it can be tested — the loop is in §3's item and in docs/session/worklog.md.
- Debuggable dev builds allow the -e extras (C4 gate). RB_RELEASE=1 builds a release that
  ignores every -e path.
- `-e repack <name>` keeps the ORIGINAL package name. To make a `.rb` copy add `-e rename 1` —
  without it the signed APK collides with the installed original and `adb install` fails with
  "signatures do not match".
- `adb install` cannot read a device path: `adb pull` the signed APK first, then install it.
  That bypasses PackageInstaller, so a test conversion needs no dialog.
- Scripted device work: `-e stage <file>` copies from getExternalFilesDir, `-e repack <name>
  -e install 0` converts without installing. FORCE-STOP the launcher between intents — the
  activity only reads extras in onCreate.
- `adb shell` from Git Bash mangles `/sdcard/...` into a Windows path: prefix the command with
  MSYS_NO_PATHCONV=1.
- The tablet can be in landscape (a game rotates it), and then every hard-coded tap misses.
  Read bounds from `uiautomator dump` instead of scaling a screenshot.
- `uiautomator dump` can hand back a STALE tree: it reported "READY" on the four tiles that
  were already painted CAN'T PLAY HERE. Take `adb exec-out screencap -p` as the truth and use
  the dump only for tap coordinates.
- Reading one file out of an installed APK without pulling 500 MB:
  `adb exec-out "unzip -p <apk> lib/armeabi-v7a/libmain.so" > x.so` (the device has
  /system/bin/unzip), then llvm-nm from the NDK on it.
- The launcher's own logcat tag is RetroBug; the guest runtime's is RBRUNTIME. A stalled run now prints
  `stall:` lines (one per guest thread, adopted first) after 10 s with no retired guest instruction; they
  name pc/lr/sp against modules, the wait kind and futex word, and a stack scan.
- Java stacks on a stalled repack: repack with `-e debuggable 1`, then
  `adb forward tcp:8700 jdwp:<pid>` and `jdb -connect com.sun.jdi.SocketAttach:hostname=localhost,port=8700`
  (`suspend`, then `where all`, then `resume`). `kill -3` writes to tombstoned and is not in a bugreport.
- Managed-method tracing: `build/patch/` holds a PowerShell + Mono.Cecil tracer (`trace.ps1`/`trace2.ps1`)
  that prepends `Debug.Log("RBTRACE <type.method>")` to every Awake/Start/OnEnable, plus `zipapk.ps1` to
  rebuild an APK with patched managed DLLs; hand it to the normal `-e stage`/`-e repack` path. `dotnet`
  has no SDK installed; load Cecil with `[Reflection.Assembly]::Load([IO.File]::ReadAllBytes(...))`
  (Add-Type refuses the Downloads path). These tools live under build/ (ignored) and are not shipped.
- M5 per-game evidence: build/m5/<pkg>/ (repack.txt, logcat.txt, shot1/2.png, final.txt).
- A converted copy's boot report is logcat tag RBRUNTIME plus
  /data/user/0/<pkg>/files/rb-report.txt (readable with `run-as` only for the launcher; for a
  copy use logcat).
